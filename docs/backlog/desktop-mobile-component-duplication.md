# дублирование `*Desktop`/`*Mobile` компонентов вместо адаптивной верстки

Сейчас весь проект построен на парных компонентах `*Desktop`/`*Mobile`, переключаемых рантайм-хуком
`useViewport()` (`src/shared/lib/viewport/useViewport.ts`, брейкпоинт 720px) — задокументированный
паттерн в `AGENTS.md` ("Responsive pattern"). Он затрагивает практически каждую страницу и виджет:
`HomeDesktop`/`HomeMobile`, `SearchDesktop`/`SearchMobile`, `MovieDesktop`/`MovieMobile`,
`FavoritesDesktop`/`FavoritesMobile`, `PopularDesktop`/`PopularMobile`,
`RecommendationsDesktop`/`RecommendationsMobile`, плюс `Card`/`MobileCard` (`@entities/movie`),
`mobile-chrome` (`MobileHeader`, `BottomNav`) и логика внутри `movie-rail`.

Нужно отказаться от этого дублирования и перейти на единую адаптивную верстку по методологии
mobile-first: один набор компонентов на страницу/виджет, поведение и раскладка меняются через
CSS (media queries, flex/grid, fluid-типографику) от мобильной базы вверх, а не через параллельные
React-деревья с идентичной бизнес-логикой, продублированной в двух версиях.

Объём и риски (почему не делается прямо сейчас): это сквозной архитектурный рефакторинг, а не
точечный фикс — придётся пересмотреть структуру каждой страницы/виджета, слить дублирующуюся
разметку и стили, обновить `AGENTS.md` (сам паттерн задокументирован как обязательный для новых
компонентов) и, вероятно, пересмотреть часть тестов, завязанных на `useViewport`/раздельный рендер
`*Desktop`/`*Mobile`. Нужно отдельное планирование (порядок миграции по страницам, что делать с
`useViewport` — оставить для немногих действительно JS-зависимых развилок или убрать полностью).
