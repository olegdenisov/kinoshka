# трейлер нельзя воспроизвести — play-кнопка просто открывает ссылку в новой вкладке

На `/movie/:id` обе кнопки трейлера — `<a href={trailerUrl} target='_blank'>` (`MediaTab.tsx:24-31` и
`MovieHero.tsx:97-107`), то есть клик уводит на внешний ресурс вместо воспроизведения внутри приложения.

**Почему отложено (замер 2026-10-01):** API сейчас не отдаёт трейлеры вообще. `/v1.4/movie` с
`notNullFields=videos.trailers.url` возвращает `total: 0`, у девяти самых популярных карточек `videos`
равно `null` и в детальном эндпоинте. Обе кнопки на живых данных не рендерятся, плеер было бы не на чем
открыть и проверить, а форматы URL и хосты для CSP пришлось бы угадывать.

**Что решит вопрос:** API начал отдавать `videos` (тот же запрос с `notNullFields` даёт `total > 0`) либо
выбран другой источник трейлеров (например, поиск по YouTube Data API — это отдельная задача с ключом,
квотой и новым хостом в `connect-src`).

Решения и ловушки из планирования, чтобы не выяснять заново:

- Форма: одна модалка на нативном `<dialog>`, открывается из обеих точек входа; iframe/video монтируется
  только при открытии. Нераспознанный источник остаётся внешней ссылкой.
- Провайдеры выбирать по реальному распределению хостов в API, а не заранее. Embed-URL собирать из
  извлечённого ID на фиксированном хосте, сверяя `hostname` с точным списком; URL из API в `src` не
  пробрасывать.
- CSP: в `vercel.json` нет `frame-src`/`media-src`, действует `default-src 'self'`. Список хостов держать в
  модуле без импортов: корневой `vercel-headers.test.ts` типизируется `tsconfig.node.json` без alias-путей,
  импорт файла с `@shared/api` роняет `make typecheck`.
- oxlint: `onClick` на `<dialog>` (закрытие по подложке) и `<video>` без `<track>` не проходят jsx-a11y.
- jsdom 30 не реализует `showModal()`/`close()` — нужен стаб в `src/test/setup.ts`; под `StrictMode`
  повторный `showModal()` бросает `InvalidStateError`.
- `Movie.test.tsx:257` ищет трейлер по `role='link'` — после замены на `<button>` проверка станет пустой.
