# нет блока профиля — аватар и nav-пункт "Profile" ничего не делают

На проекте пока нет ни одного реального UI-блока, привязанного к пользователю — только статичные
заглушки: `Header.tsx:202` и `MobileHeader.tsx:54` рендерят захардкоженный
`<div className={s.avatar}>AV</div>` (не имя, не логин, никуда не ведёт), а `BottomNav.tsx:31`
держит пункт `profile` с `path: null` — задизейблен намеренно (см. тест `BottomNav.test.tsx:48`,
явно проверяющий, что клик по нему не навигирует).

Нужен настоящий profile-блок: имя/логин пользователя, кнопки/ссылки авторизации, быстрый доступ к
избранному (`/favorites` уже есть и работает, `@features/favorites`), мой список, просмотрено, рейтинг, рекомендации и т.п.

Неопределённость, из-за которой `worth: later`, а не `yes`: авторизация в проекте по плану
(`plans/roadmap.md`, Фаза 5) появляется нескоро и в совсем другой архитектуре — BFF-ветки с
сессиями/OAuth/WebAuthn, отдельные ветки монорепо, не `main`. Строить сейчас полноценный
profile-блок с «кнопками для авторизации» не на что опереться — реального auth нет и не
планируется в текущей фазе `main`. Нужно решить: либо (a) сделать блок раньше Фазы 5 как
client-only заглушку (ссылка на `/favorites` + видимое место под будущее имя/логин, без реальной
авторизации), либо (b) отложить до тех пор, пока в одной из auth-веток (5.1-5.3) не появится
реальная сессия, и тогда делать сразу с бэкендом. Пока направление не выбрано — фиксировать
конкретную реализацию рано.
