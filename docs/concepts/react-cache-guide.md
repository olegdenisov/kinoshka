# React `cache()`

`cache()` --- одна из самых интересных возможностей современного React
(стабилен с React 19). На первый взгляд она выглядит как обычная
мемоизация, но **это не `useMemo` и не аналог memoize из lodash**. Это
механизм React для **дедупликации и кеширования асинхронных ресурсов во
время рендера**.

Важно понимать ее назначение, иначе ее очень легко использовать
неправильно.

> ⚠️ **`cache()` работает только в React Server Components** (условие
> сборки `react-server`). В обычном клиентском React-приложении --- как
> Kinoshka сейчас, чистый Vite SPA без RSC-фреймворка --- вызов
> `cache()` **ничего не кеширует**: функция просто выполняется заново
> при каждом вызове, без ошибки и без предупреждения. Использовать
> этот API в текущем кодбейзе бессмысленно, пока в проекте не появится
> серверный рендеринг (Next.js App Router и т. п.).

## Зачем появился `cache()`

Представим компонент.

```tsx
function UserPage({ id }: Props) {
  const user = use(fetchUser(id))
  return <UserCard user={user} />
}
```

Каждый рендер создает новый Promise, поэтому React считает его новым
ресурсом.

### Решение

```tsx
const fetchUserCached = cache(fetchUser)
```

Теперь:

```tsx
use(fetchUserCached(id))
```

будет получать один и тот же Promise для одинаковых аргументов в рамках
текущего кеша React.

## Что делает `cache()`

После:

```tsx
const cached = cache(fetchMovie)
```

React кэширует результат вызова по аргументам. Повторный вызов с теми же
аргументами возвращает тот же Promise.

## Сравнение аргументов

Сравнение происходит через `Object.is()`: **примитивы** (числа, строки,
булевы) сравниваются **по значению**, а **объекты, массивы и функции**
--- **по ссылке (identity)**.

Работает (примитив, сравнение по значению):

```tsx
cachedUser(10)
cachedUser(10)
```

Не работает как ожидают многие (объект, сравнение по ссылке):

```tsx
cachedSearch({ page: 1 })
cachedSearch({ page: 1 })
```

Это разные объекты и разные ключи кеша.

## `cache()` + `use()`

```tsx
const getMovies = cache(async () => {
  const response = await fetch('/movies')
  return response.json()
})

function Movies() {
  const movies = use(getMovies())
}
```

## Несколько компонентов

Если несколько компонентов вызывают:

```tsx
use(fetchUserCached(5))
```

будет выполнен один запрос, а все компоненты получат один и тот же
Promise.

## Это не глобальный кеш

`cache()` **не заменяет** RTK Query или TanStack Query. Он предназначен
для дедупликации ресурсов в рамках жизненного цикла кеша React, а не для
долговременного хранения данных.

## Server Components

`cache()` работает **только** в Server Components: там несколько
компонентов могут безопасно разделять один запрос к данным в рамках
одного серверного запроса, после чего кеш инвалидируется. Вне
Server Components (клиентские компоненты, обычный SPA) `cache()` не
выполняет никакой дедупликации.

## Особенности, о которых легко забыть

- **Ошибки тоже кешируются.** Если функция бросает исключение для
  конкретных аргументов, эта ошибка попадает в кеш и будет повторно
  выброшена при следующем вызове с теми же аргументами --- функция
  повторно не выполнится.
- **Кеш доступен только внутри рендера компонента.** Вызов
  мемоизированной функции вне рендер-цикла компонента (например, на
  уровне модуля) просто выполнит исходную функцию напрямую, не
  обращаясь к кешу и не сохраняя в него результат.
- **Вызывайте `cache()` на уровне модуля**, а не внутри компонента ---
  иначе каждый рендер будет создавать новую (пустую) мемоизированную
  функцию.

## Что `cache()` не умеет

- TTL
- background refresh
- stale-while-revalidate
- optimistic updates
- polling
- инвалидацию
- retry

## Когда применять

Используйте `cache()`, если:

- работаете с Server Components;
- используете `use()`;
- строите приложение вокруг Suspense;
- хотите дедупликацию запросов.

## Когда не применять

Для обычных SPA с клиентским кешем и синхронизацией данных лучше
использовать RTK Query или TanStack Query.

## Практическое правило

Задача Инструмент

---

Дедупликация ресурса `cache()`
Чтение ресурса `use()`
Loading UI `Suspense` / `AsyncBoundary`
Ошибки `ErrorBoundary` / `AsyncBoundary`
Клиентский кеш RTK Query / TanStack Query

В связке React 19 `cache()`, `use()` и `Suspense` образуют единый
механизм работы с асинхронными ресурсами.
