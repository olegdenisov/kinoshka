# 🎬 Frontend-проект: Каталог фильмов, сериалов и анимации

- **Роль:** production-ready frontend
- **Цель:** Middle → Senior
- **Фокус:** архитектура, масштабируемость, контроль состояния, performance

---

## 1. Описание проекта

### 1.1 Идея проекта как продукта

Приложение — каталог видеоконтента (фильмы, сериалы, анимация) с возможностью:

- просматривать контент по категориям,
- искать и фильтровать,
- изучать детальную информацию,
- формировать персональную подборку,
- получать рекомендации.

Проект не «IMDb-клон», а демонстрация архитектурных решений, применимых в реальном продукте.

### 1.2 Пользовательские сценарии

**Базовые (MVP):**

- Пользователь заходит на главную → видит каталог контента.
- Ищет фильм по названию.
- Фильтрует по жанрам / году / рейтингу (в рамках API).
- Открывает страницу деталей.
- Просматривает рейтинг, описание, метаданные.

**Продвинутые (Senior-level):**

- Добавляет контент в избранное.
- Возвращается позже — избранное сохранено.
- Видит популярное за неделю.
- Получает рекомендации на основе предпочтений.
- Переключает тему (light / dark).
- Приложение остаётся быстрым даже при больших списках.

### 1.3 Почему выбран этот стек

**React + TypeScript**

- индустриальный стандарт,
- богатая экосистема,
- предсказуемая модель рендера,
- строгая типизация как инструмент архитектуры.

**Feature-Sliced Design 2.0**

- архитектура ориентирована на рост,
- явное разделение ответственности,
- снижает coupling между частями приложения.

## 3. Фичи

### 🟢 MVP-фичи

#### 3.1 Каталог контента

- **Бизнес-цель:** основной value приложения.
- **Источник данных:** poiskkino.dev (list endpoints).
- **FSD-уровень:** `features/content-list`
- **Решения:**
  - разделение UI и data-логики,
  - загрузка чанками,
  - агрегация состояний loading/error.

#### 3.2 Карточки контента

- **Цель:** визуальная навигация.
- **Данные:** минимальный набор (poster, title, rating).
- **FSD:** `entities/content`
- **Решение:**
  - dumb-компонент,
  - memoization (React.memo).

#### 3.3 Поиск и фильтрация

- **Цель:** UX.
- **Источник:** API query params.
- **FSD:** `features/search`, `features/filters`
- **Trade-off:**
  - debounce на клиенте,
  - не храним search results глобально без необходимости.

### 🔵 Advanced / Senior-level фичи

#### 3.4 Избранное ⭐

- **Бизнес-цель:** retention.
- **Источник:** localStorage.
- **FSD:** `features/favorites`
- **Решения:**
  - хранение только ID,
  - lazy-инициализация,
  - синхронизация при старте приложения.
- **Edge cases:**
  - удалённый контент,
  - очистка storage,
  - несовпадение схем данных.

#### 3.5 Популярное за неделю 🔥

- **Цель:** engagement.
- **Источник:** API (если есть соответствующий endpoint).
- **FSD:** `features/weekly-popular`
- **Ограничение:** не кешируем агрессивно без подтверждённого SLA API.

#### 3.6 Рекомендации 🎯

- **Тип:** rule-based (не ML).
- **Источник:**
  - жанры избранного,
  - средний рейтинг,
  - тип контента.
- **FSD:** `features/recommendations`

#### 3.7 Тёмная тема 🌙

- **Цель:** accessibility + UX.
- **Источник:** localStorage.
- **FSD:** `features/theme`
- **Решение:**
  - design tokens,
  - отсутствие inline-стилей.

#### 3.8 Feature Flags 🧪

- **Цель:** управляемость фичей.
- **Источник:** config (static).
- **FSD:** `shared/config`
- **Решение:**
  - флаги читаются на старте,
  - не смешиваются с бизнес-логикой.

#### 3.9 Performance optimizations 🧠

- list virtualization,
- memoized selectors в Reatom,
- нормализация данных при необходимости,
- минимизация prop-drilling.

## 4. Архитектура (FSD)

### 4.1 Слои FSD

| Слой | Назначение |
|---|---|
| `app` | bootstrap, providers, routing |
| `processes` | (опционально) сложные пользовательские потоки |
| `pages` | композиция фичей |
| `widgets` | крупные UI-блоки |
| `features` | бизнес-действия пользователя |
| `entities` | доменные модели |

## 5. Требования (Senior-level)

### Функциональные

- все сценарии воспроизводимы,
- корректная работа при ошибках API.

### Нефункциональные

- отсутствие лишних ререндеров,
- предсказуемость side-effects,
- готовность к росту данных.

### Кодстайл / DX

- strict TS,
- явные типы API,
- читаемая структура проекта.
